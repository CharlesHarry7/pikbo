# Pikbo repository and production audit — 2026-07-27

## Executive finding

Pikbo already builds and has a broad public surface, but it is not ready for
unrestricted live generation. The immediate risk is provider spend, not missing
pages:

- `pikbo.ai` reports `live-generate` and a configured FAL provider.
- Authentication and durable credits are disabled in production.
- A new unsigned-in browser session receives 10 cookie credits.
- Deleting or omitting the cookie creates another free session.
- rate limits, job locks, assets and job history are process-memory only.
- Free live output is fail-closed because no server-owned watermarked derivative
  exists, so Pikbo can pay for a generation the free visitor cannot download.

Decision: anonymous users are cached-demo-only until login, atomic durable
reservation and server-owned delivery exist.

## Verified positive state

- Production build succeeds with 193 generated routes.
- TypeScript and engine smoke pass.
- ESLint has no errors and two unused-import warnings.
- GitHub Actions and the latest Vercel commit status are green.
- Stripe is disabled.
- Raw free-provider downloads are blocked.
- Public robots, canonical/noindex handling and the 13-URL sitemap are broadly
  coherent.

These checks do not prove the billing or generation state machine is safe.

## P0 engineering findings

### A1 — Renewable anonymous FAL trial

`lib/session.ts` creates a new 10-credit guest whenever the signed cookie is
missing. `app/api/generate/route.ts` treats those cookie credits as authority
before invoking FAL. `lib/rateLimit.ts` uses process-local maps.

Acceptance:

- anonymous requests never enter the live provider path;
- deleting cookies cannot create another paid-model trial;
- live generation requires an authenticated user and a durable reservation.

### A2 — Durable credits do not fail closed

The current shadow reservation logs durable failures but permits the cookie path
to continue. Setting a durable-credits flag therefore does not guarantee durable
accounting.

Acceptance:

- provider invocation requires a committed database reservation ID;
- reservation failure, timeout or database unavailability returns an error before
  provider invocation;
- an idempotency key maps to one reservation and one job.

### A3 — Free live has no deliverable

The file-watermark pipeline is correctly marked blocked. Free raw downloads are
blocked, but this means a paid provider call can complete without a playable or
downloadable customer asset.

Acceptance:

- keep Free live disabled until a server-owned derivative exists;
- storage keeps source, raw output, watermarked output and poster separate;
- free users receive only the baked-watermark derivative.

## P1 engineering findings

- Supabase wallet update, reservation and ledger writes are separate operations,
  not one transaction.
- retry promotion guesses a queued job by effect or prompt and can select the
  wrong version.
- browser polling refreshes open-job TTL and can keep orphan jobs alive.
- CI runs `critical-path` with `|| true`.
- `engine-smoke.mjs` is 5,453 lines and often checks source strings or duplicated
  simplified logic instead of production-route behavior.
- the public health endpoint mutates reservation state and reveals internal paths.
- production session-secret fallback must fail startup instead of using a known
  default.

## Product findings

- The repository constitution correctly defines Toy Launch Pack as the product
  unit, but the public funnel still emphasizes one free clip.
- The homepage uses all 12 demos even though the release whitelist contains eight.
- Concept Recipes borrow videos from other effects and remain playable/remixable.
- 12 registered examples are not 12 equally proven cases: six are prototypes.
- three indexed tool pages reuse the same sample video.
- static 4/5 scores are not an auditable human quality review.
- Create exposes intents, model shelves, prompts and advanced controls before the
  first simple seller result.
- the current three-output product is a Seller Starter Pack, not the unimplemented
  12-output Launch Pack.

Immediate product path:

`upload one owned toy → choose a sales goal → confirm a 3-output Starter Pack →
generate and review each output → export pack → start the next SKU`

## Growth and WorkBuddy findings

- GSC evidence is approximately 6 impressions and 0 clicks, too little to judge
  title or keyword performance.
- directory forms were submitted, but no public verified backlink URL was
  produced; verified new backlinks should currently be counted as zero.
- `intitle:0` is not evidence of demand. Unverified “50–500 searches,” “blue
  ocean,” “already ranking” and “20 zero-competition keywords” must not drive
  page expansion.
- no GA/gtag was found, so visit-to-pack and second-SKU funnels are not measured.
- WorkBuddy's direct-main GitHub API script reads an OAuth token from Keychain
  and bypasses normal PR review.

Decision:

- WorkBuddy is restricted to research, GSC, SERP evidence and external-status
  verification.
- no production secrets, database, deploy, business-code or direct-main access;
- no new indexed pages until current pages have distinct proof, usable tools and
  measurable seller conversion.
